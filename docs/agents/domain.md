# Domain Docs

The engineering skills use a single-context layout for this repo.

## Before exploring

Read root `GLOSSARY.md` and relevant ADRs in `docs/adr/` when they exist. Proceed if they do not exist; create them when domain terms or decisions are resolved.

## Layout

- `GLOSSARY.md`: shared domain vocabulary
- `docs/adr/`: architecture decisions

Use glossary terms in issues, proposals, hypotheses, and tests. If a needed term is missing, reconsider it or note the gap for domain modeling. Explicitly flag any proposal that conflicts with an existing ADR.
